## Scope

Add ETDM **Domains** as a child of Technology, mirroring the existing Technology admin module (auth, layout, tokens, react-query hooks, audit trigger pattern, soft-delete + clone RPCs, CSV export). Existing Technology functionality is untouched except a new "Domains" tab on the profile.

## Database (single migration)

**New enums**
- `etdm_domain_lifecycle` — Emerging, Evaluation, Strategic, Active, Maintenance, Legacy, Deprecated, End of Support, Retired
- `etdm_domain_approval` — Draft, In Review, Approved, Rejected, Retired
- `etdm_domain_criticality` — Mission Critical, Business Critical, Important, Standard, Noncritical

**`etdm_master_domains`** (controlled reference list)
- `id uuid PK`, `name text unique`, `display_order int`, `is_active bool`, timestamps
- Seeded with the 16 approved Master Domains from the spec
- Grants: `SELECT` to authenticated + service_role; writes to service_role only
- RLS: authenticated read; only `is_platform_admin(auth.uid())` writes

**`etdm_domains`** — every column from spec sections 4 and 12:
- Identity: `id uuid PK`, `tenant_id uuid`, `technology_id uuid REFERENCES etdm_technologies(id) ON DELETE RESTRICT`, `master_domain_id uuid REFERENCES etdm_master_domains(id) ON DELETE RESTRICT`, `domain_display_name`, `short_name`, `slug`, `description`, `display_order int NOT NULL DEFAULT 0`, `tags text[]`
- Business: `scope_summary`, `business_purpose`, `business_criticality etdm_domain_criticality NOT NULL`
- Governance: `lifecycle_status etdm_domain_lifecycle NOT NULL`, `approval_status etdm_domain_approval NOT NULL DEFAULT 'Draft'`, `is_active bool NOT NULL DEFAULT false`, `is_deleted bool NOT NULL DEFAULT false`, `effective_date`, `review_date`, `expiration_date`, `governance_notes`, `source_of_record`, `external_reference_id`
- Metadata: `created_by`, `created_at`, `updated_by`, `updated_at`, `published_version int NOT NULL DEFAULT 1`, `cloned_from_domain_id uuid REFERENCES etdm_domains(id)`, `deleted_by`, `deleted_at`
- Constraints: `UNIQUE (technology_id, slug) WHERE is_deleted=false`; partial unique `(technology_id, master_domain_id) WHERE is_deleted=false` to enforce "no duplicate Master Domain per Technology"
- Indexes on `technology_id`, `master_domain_id`, `is_deleted`, `(technology_id, display_order)`

**Grants (required)**
```
GRANT SELECT, INSERT, UPDATE, DELETE ON public.etdm_domains TO authenticated;
GRANT ALL ON public.etdm_domains TO service_role;
GRANT SELECT ON public.etdm_master_domains TO authenticated;
GRANT ALL ON public.etdm_master_domains TO service_role;
```

**RLS on `etdm_domains`**
- `SELECT/INSERT/UPDATE/DELETE` all gated by `is_platform_admin(auth.uid())` — same pattern as `etdm_technologies`

**Triggers**
- `update_updated_at_column` BEFORE UPDATE
- `etdm_write_audit_domains()` — new SECURITY DEFINER trigger cloned from `etdm_write_audit` but writes `entity_type='domain'` to the existing `etdm_record_audit_log` (reuses the audit table). Captures create/update/soft_delete/restore/activate/deactivate/approval_status_change, and always includes changed_fields (covers display_order and tags automatically).

**RPCs**
- `etdm_clone_domain(_source_id uuid) RETURNS etdm_domains` — platform-admin only; resets `approval_status='Draft'`, `is_active=false`, `is_deleted=false`, generates new slug suffix, sets `cloned_from_domain_id`, `created_by`, `updated_by`
- `etdm_reorder_domains(_technology_id uuid, _ordered_ids uuid[]) RETURNS void` — platform-admin only; single-transaction UPDATE that sets `display_order` from array index, so drag-drop is one round trip and audits fire per row

## Frontend

**Types** — regenerated by Supabase after migration.

**New hooks** in `src/hooks/etdm/useDomains.ts`
- `useDomains({ technologyId?, filters, page, pageSize, sort, search })` — paginated list with count
- `useDomain(id)`, `useCreateDomain`, `useUpdateDomain`, `useSoftDeleteDomain`, `useRestoreDomain`, `useActivateDomain`, `useDeactivateDomain`, `useCloneDomain`, `useReorderDomains`, `useBulkSoftDeleteDomains`, `useMasterDomains`
- Query keys `["etdm-domains", ...]`, `["etdm-domain", id]`, `["etdm-master-domains"]`

**New pages / components**
- `src/pages/admin/technology-taxonomy/domains/DomainsPage.tsx` — list at `/admin/technology-taxonomy/domains`. Full CRUD table: search, filters (Technology, Master Domain, Lifecycle, Approval, Criticality, Active, Tenant, Created/Modified date), sorting, server-side pagination, refresh, column chooser (localStorage), bulk soft-delete, CSV export (filtered + selected, includes parent Technology name), loading/empty/error states.
- `src/pages/admin/technology-taxonomy/domains/DomainProfilePage.tsx` — Add / View / Edit / Clone. Sections: Identity, Business, Governance, Metadata (read-only). Slug auto-generated from display name with manual override; duplicate-display-name soft warning; unsaved-change guard via `beforeunload` + route block; zod validation with required-field enforcement; header shows Master Domain, Display Name, Parent Technology link, Lifecycle badge, Approval badge, Criticality.
- `src/components/etdm/DomainsTab.tsx` — inserted as a new tab on `TechnologyProfilePage`. Lists this Technology's domains ordered by `display_order`, columns per spec (Display Order, Master Domain, Display Name, Business Criticality, Lifecycle, Approval, Active, Last Modified, Actions). "Add Domain" primary button navigates to profile page prefilled with `technology_id`. Drag-and-drop reordering via `@dnd-kit/core` + `@dnd-kit/sortable` (already common); on drop, calls `useReorderDomains`.
- `src/components/etdm/DomainBadges.tsx` — small reusable badge components for lifecycle/approval/criticality (semantic tokens, not raw colors).

**Row actions:** View, Edit, Clone, Activate, Deactivate, Soft Delete — all with confirmation dialog. No hard delete.

**Routing (`src/App.tsx`)** — all `<ProtectedRoute requireAdmin>` (same gate the existing Technology pages use — this is the app's current mapping for platform-admin-only access):
- `/admin/technology-taxonomy/domains`
- `/admin/technology-taxonomy/domains/new`
- `/admin/technology-taxonomy/domains/:domainId`
- `/admin/technology-taxonomy/domains/:domainId/edit`

**Navigation** — Add a "Domains" tile alongside "Technology Taxonomy" on the Settings > Enterprise Administration section, and a "Domains" link on the Technology Taxonomy landing page header.

## Non-goals / assumptions
- Reuses existing sidebar, `ProtectedRoute requireAdmin`, `etdm_record_audit_log`, design tokens, shadcn form/table components, sonner toasts, react-query — no duplicate infrastructure.
- No customer-facing surface; all routes admin-only.
- Real drag-and-drop via `@dnd-kit` (adding if not already installed).

## Verification
- Migration applies, master domains seeded (16 rows).
- Create Technology > open Profile > new **Domains** tab renders empty state.
- Add Domain, Clone, Activate, Deactivate, Soft Delete each show in `etdm_record_audit_log` with `entity_type='domain'`.
- Drag-drop reordering persists after refresh; audit rows show `changed_fields = ['display_order']`.
- Attempting to add two domains with the same Master Domain to the same Technology is rejected by the partial unique index (surfaced as a toast).
- Non-admin user gets 403 on all `/admin/technology-taxonomy/domains*` routes.
- CSV export contains parent Technology name column.
