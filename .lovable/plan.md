
# Auto-Build Standard Domains — Implementation Plan

## Goal
Add an admin action that creates the 16 standard ETDM `etdm_domains` child records for a selected Technology, safely and repeatably. Available in two places:
- Technology Profile → Domains tab (Technology already known)
- Domain Administration page (Technology picker)

Never creates duplicates, never overwrites, always audit-logged, always tenant-scoped.

---

## 1. Database changes (one migration)

**a. Partial unique index — prevents duplicate active standard domains**
```
CREATE UNIQUE INDEX IF NOT EXISTS etdm_domains_unique_active_master_per_tech
ON public.etdm_domains (technology_id, master_domain_id)
WHERE is_deleted = false;
```

**b. RPC `public.etdm_auto_build_domains(_technology_id uuid, _master_domain_ids uuid[])`**
- SECURITY DEFINER, `search_path = public`.
- Guards: `is_platform_admin(auth.uid())` required (matches existing `etdm_clone_domain`/`etdm_reorder_domains`).
- Loads the parent `etdm_technologies` row (must be `is_deleted = false`); errors `technology_not_found` otherwise.
- Iterates active master domains in `_master_domain_ids`:
  - Skips any that already have an active (`is_deleted = false`) row for this technology.
  - Skips inactive master domains.
  - Inserts new row with defaults per spec (see §2 field mapping).
- Runs inside a single transaction (implicit in a plpgsql function) — any failure rolls the entire call back.
- Writes one `etdm_record_audit_log` row with `entity_type='technology'`, `action='auto_build_domains'`, `new_values` = summary jsonb `{ created_ids, skipped_existing_ids, skipped_inactive_master_ids, requested_master_ids }`. The per-row `etdm_write_audit_domains` trigger already emits standard `create` audits for each new domain — no duplication needed.
- Returns `jsonb` with `{ created: Domain[], skipped_existing: uuid[], skipped_inactive: uuid[] }`.

**c. Field defaults for each new row (per spec §6/§7)**
| Field | Value |
|---|---|
| tenant_id | parent technology's tenant_id |
| technology_id | `_technology_id` |
| master_domain_id | master.id |
| domain_display_name | master.name |
| short_name | master.short_name |
| slug | `${technology.slug}-${slugify(master.name)}` (unique index on `(tenant_id, slug)` already handled; suffix `-N` on conflict) |
| description | `Defines how the {master.name} domain applies to {tech.technology_name}, including its scope, responsibilities, governance, and related capabilities.` |
| display_order | master.display_order |
| tags | `{ETDM, "Technology Domain", tech.technology_name, master.name}` |
| business_criticality | `COALESCE(tech.business_criticality, 'Standard')` |
| lifecycle_status | `'Evaluation'` |
| approval_status | `'Draft'` |
| is_active | `false` |
| is_deleted | `false` |
| source_of_record | `'ETDM Standard Domain Auto-Build'` |
| governance_notes | `'Auto-generated by ETDM Auto-Build on <ts>. Review and complete before activation.'` |
| created_by / updated_by | `auth.uid()` |
| published_version | `1` |

Existing rows are never touched (§19).

## 2. Frontend — new hook & shared preview dialog

**`src/hooks/etdm/useAutoBuildDomains.ts`** — wraps `supabase.rpc('etdm_auto_build_domains', …)`, invalidates `etdm-domains*` query keys.

**`src/components/etdm/AutoBuildDomainsDialog.tsx`** — reusable dialog:
- Props: `open`, `onOpenChange`, `technologyId?`, `technology?` (when caller already has it, e.g., profile page — hides the picker), `onBuilt?`.
- If no technology supplied → shows searchable Technology combobox (uses `useTechnologyOptions`, adds vendor/practice/lifecycle columns) and requires selection.
- Loads `useMasterDomains()` + `useDomainsForTechnology(tech.id)` to compute preview rows:
  - **Ready to Create** — no existing active row (default checked).
  - **Already Exists** — existing active row (disabled, unchecked).
  - **Inactive Master Domain** — master.is_active = false (disabled).
- Summary counts: Standard 16, Existing, New to create, Skipped, Conflicts.
- Grid columns: Include ▢ / Order / Master Domain / Status / Proposed Display Name / Existing / Action.
- Buttons: Cancel, `Build Selected Domains` (disabled when 0 selected).
- On confirm → calls RPC, then shows result summary with counts and "View Domains" + "Close" actions.

## 3. Wire-up

**`src/components/etdm/DomainsTab.tsx`** — add `Auto-Build Domains` secondary button immediately to the left of the existing `Add Domain` button. Also update the empty-state to expose both actions. Add a coverage badge in the tab header: `Standard Domain Coverage: X of 16`.

**`src/pages/admin/technology-taxonomy/domains/DomainsPage.tsx`** — add `Auto-Build Domains` toolbar action that opens the same dialog with the technology picker enabled.

---

## 4. Permissions
All entry points already sit under the admin technology-taxonomy area (platform-admin gated). The RPC re-checks `is_platform_admin(auth.uid())` server-side. Existing RLS on `etdm_domains` (which restricts insert/update to platform admins) is unchanged.

---

## 5. Out of scope for this change
- Restoring soft-deleted matches ("Restore Existing Domain" action) — spec §13 asks for it as a separate explicit path; will be handled in a follow-up.
- New `Coverage` column on Domain admin list page (§16) — can be added incrementally.
