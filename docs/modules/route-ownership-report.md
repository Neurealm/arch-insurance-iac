## Classification policy

Applied in `src/modules/routeOwnership.ts`, in order:

1. Exact route match against a manifest's `boundaries.routes` → `module-owned`.
2. Route prefix match against `boundaries.routePrefixes` → `module-owned`.
3. Two or more modules claim the same path → `ownership-conflict` (none observed).
4. Path under a platform prefix (`/platform`, `/auth`, `/login`, `/signup`,
   `/accept-invitation`, `/reset-password`, `/settings`, `/profile`) → `platform-owned`.
5. Route wrapped in a shared provider or rendered by a shared layout that more than
   one module uses → `shared`.
6. Computed/dynamic path that cannot be statically resolved → `unable-to-verify`.
7. Everything else → `unregistered`.

## Shared routes (12)

Routes rendered inside providers or layouts that are not owned by any single
module: the `ScenarioStateProvider` wrapper, `GuidedInvestigationProvider`,
`EvidenceGraphProvider` and the shared EOC shell. These are counted as `shared`
rather than assigned to SRE, because assigning them would silently transfer
ownership of cross-module infrastructure.
